# DHPE Content Automation

מערכת אוטומציית תוכן לאתר [dhpe.co.il](https://dhpe.co.il) — דניאל חסיד פרויקטים בחינוך.

הריפו מכיל גם את **שולחן המסחר ביננס** — צוות סוכני השקעות (ר' בהמשך).

## מה המערכת עושה

מפיקה 2 פוסטי SEO בשבוע לאתר הוורדפרס, כולל:
- מחקר מילות מפתח
- כתיבת פוסט 1500-2000 מילים
- חבילת SEO מלאה (Meta, OG, Schema FAQ)
- העלאה אוטומטית כטיוטה לוורדפרס
- מייל הזנה אישי לדניאל לפני כל פוסט
- מייל התראה כשהטיוטה מוכנה

# שולחן המסחר ביננס (Binance)

צוות של 7 סוכני AI להשקעות בביננס בשיטת Core + Satellite: ליבה ארוכת טווח +
תיק מסחר אקטיבי קטן. **המצב הנוכחי: Phase 0 — נייר/המלצות בלבד.**

## הצוות

| פרסונה | סקיל | תפקיד |
|---|---|---|
| **אלון** | `binance-cio` | מנהל השקעות ראשי — החלטת יום והצעות עסקה |
| **תמר** | `binance-macro-analyst` | מאקרו — משטר שוק ופונדמנטלי |
| **יואב** | `binance-technical-analyst` | טכני — סטאפים, רמות, סטופים |
| **נועה** | `binance-news-sentiment` | חדשות וסנטימנט — כולל דגל אדום שמקפיא מסחר |
| **מרים** | `binance-risk-manager` | סיכונים — וטו/אישור, חתימת טריגרים. היחידה שמאשרת |
| **איתן** | `binance-trade-executor` | ביצוע — היחיד שנוגע ב-API, רק לפי פסק דין של מרים |
| **גדי** | `binance-performance-retro` | מבקר — רטרו שבועי וכללים מחייבים (המקביל לסיסי) |

שרשרת החלטה: תמר/נועה/יואב → אלון → מרים → איתן → (בסוף השבוע) גדי.
אופן הרצה: כל סוכן רץ כסאב-איג'נט נפרד; הסשן הראשי רק מתאם ומפקח.
תקשורת בין הסוכנים — דרך קבצים ב-`trading-desk/` בלבד.

## מבנה התיקיות

```
trading-desk/
├── config/         # limits.json (מגבלות קשיחות), phase.json — רק דניאל עורך
├── KILL-SWITCH     # אם הקובץ קיים — כל ביצוע נעצר (דניאל/מרים יוצרים)
├── inbox/          # דוחות האנליסטים (market-view, technical-view, news-sentiment)
├── decisions/      # החלטות יום, trade-proposals, risk-verdict
├── state/          # active-triggers.json, portfolio-state, orders-log.jsonl, trade-journal
└── rules/          # trading-rules.md (מחייב), learnings-log.md
scripts/binance/    # הקוד: client, place_order (שערי הבטיחות), market_watcher ועוד
```

## ארכיטקטורת מוח-שריר

- **המוח:** הסוכנים רצים ב-Routine ומייצרים החלטות + טריגרים מותנים חתומים
  (עם תוקף TTL) ב-`trading-desk/state/active-triggers.json`.
- **הבורסה קודם:** כל תנאי שביננס יודעת להחזיק כפקודה נחה (LIMIT / OCO / STOP)
  מונח ישירות בבורסה — אמין יותר מכל לולאה.
- **השריר:** `scripts/binance/market_watcher.py` — סקריפט בלי LLM שמנטר מחירים
  ומבצע טריגרים שהתנאי שלהם התקיים, עם אותם שערי בטיחות בדיוק.
  **חייב לרוץ על מארח קבוע** (VPS / Raspberry Pi / מחשב דולק) — לא ב-sandbox.

## מודל שלבים

| Phase | מצב | תנאי קידום |
|---|---|---|
| 0 | נייר/המלצות (נוכחי) | ברירת מחדל; גם fallback כשאין egress |
| 1 | Testnet | צנרת נייר נקייה + מפתחות testnet כ-env secrets |
| 2 | חי, בתקרות זעירות | שבועיים / 10 עסקאות נקיות ב-testnet |

קידום שלב = עריכה ידנית של `trading-desk/config/phase.json` על ידי דניאל בלבד.

## אבטחה — לקרוא לפני הכול

- **מפתחות API לעולם לא בריפו.** env secrets בלבד: `BINANCE_API_KEY/SECRET`,
  `BINANCE_TESTNET_API_KEY/SECRET`.
- בצד ביננס: הרשאת spot trade בלבד, **משיכות (withdrawals) כבויות לתמיד**,
  IP whitelist אם למארח יש IP קבוע.
- כל פקודה עוברת את שערי `place_order.py`: kill-switch, phase, רשימה לבנה,
  תקרת notional, חובת סטופ, עקיבות id. כישלון = blocked ביומן.
- `KILL-SWITCH` עוצר הכול מיידית — כולל ה-watcher החיצוני.

## לוח זמנים מתוכנן (Routine, אחרי הרצות ידניות)

| Routine | מתי | מה |
|---|---|---|
| סריקת בוקר | א'–ה' 07:30 | תמר → נועה → יואב → אלון → מרים → איתן → commit |
| רטרו שבועי | ו' 09:00 | גדי: מספרים → דפוסים → עדכון כללים → מייל לדניאל |

הערת סביבה: ה-sandbox חוסם egress לביננס (נבדק 2026-08-16). עד שיש מארח חיצוני
או אישור egress — המערכת נשארת ב-Phase 0, ונתוני שוק מגיעים מחיפוש רשת עם ציון מקור.
